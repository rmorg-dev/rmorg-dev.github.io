# ENHANCEMENT ONE
This artifact was first created when I took the CS-300 Data Structures and Algorithms course at SNHU. I took it in the Fall of 2024. The program was designed to read a CSV file of courses and their prerequisites. The original project outcome for this assignment was to show an understanding of creating, implementing, and understanding efficient data structures. I chose this initial artifact to demonstrate my growth within C++. When I initially created this artifact in my CS-300 course, I had never used C++ before and was very new to programming in general. Since I want to advance into an embedded software role at some point in the future, a fundamental demonstration of my understanding of C++ concepts as well as my growth in developing well-formatted and structured code is the perfect way to demonstrate my ability to future employers. Within the enhanced artifact, the specific skills showcased are as follows:
-	Memory Management: By adding destructors to my BinaryTree class and my Node struct, I handled a memory leak that was present in my old code. I also made sure to adhere to C++’s rule of three by explicitly deleting both the copy constructor and the copy assignment functions for Node and BinaryTree. By doing this, I made it impossible for my BinaryTree or Node to be copied and have potential compile issues like shadow-copying.
-	Modularity: My code is now split into six files to increase modularity and readability for other programmers or users. BinaryTree stores the entire data structure with no dependency on wxWidgets, meaning it can be reused if the InputValidation header & cpp file exists alongside it for string utilities. My App file stores all application lifecycle and CSV loading functions. The MainWindow and FileWindow are both GUI layers with their own functions and responsibilities. 
-	UI/UX design principles: By replacing the console menu with a GUI, I made the application more user-friendly with clearly defined buttons, text input menus, and formatted output sections which allow for easier readability by a user. I also made sure to add display messages when user input is incorrect, or there are issues with the program. This gives the user more information on how to properly use the application or what to specifically ask for help if needed.

For this enhancement, I chose outcomes 2 and 4. Outcome 2 is demonstrated within my code through consistent, industry-standard doxygen documentation for all classes and functions. By separating business logic, data structures, and GUI layers into their own dedicated files, readability is enhanced for both technical maintainers and non-technical stakeholders. Outcome 4 is demonstrated through my implementation of the GUI. By designing and implementing a GUI, I added more value to end users of my application. I also made sure to select my GUI Library, wxWidgets, carefully. My main concerns were resource usage. While Qt is more of an industry standard for C++, the resource cost is higher. Since my application is relatively simple in terms of GUI elements, I determined the extra cost to be unnecessary for such a small application. While enhancing and modifying this artifact, I learned a lot. The first learning experience occurred when I was downloading and installing wxWidgets. I learned how to install and link libraries within Visual Studio 2026 for both win32 and x64 systems. I also got more comfortable with reading documentation and learning how to integrate things on my own without the help of a guide or tutorial. There were a few times where I was confused on how to set controls or events up but using the discussion board within wxWidgets helped me understand them a little bit better. The one feature of wxWidgets that I could not figure out how to work for me properly were sizers. I came into this enhancement knowing nothing about how to implement or use a library within C++, or anything about wxWidgets. By the end, I now know how to set up a simple GUI using wxWidgets with little to no help. I also came into this project with little practice within C++. I understood the basics, but a lot of the guides and style rules I did not know about or understand (like the rule of three, not relying on “using namespace std;”, or the idea of “Include What You Use”). Reading more about how to properly structure C++ and general industry-standard practices has greatly helped improve my confidence within this language and programming in general.
